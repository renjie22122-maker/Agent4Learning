# 2026-09-28 卡死排查与修复

现场核对发现 PID 45376 是 `pip-script.py list`，真正服务为 PID 11176。
服务 CPU 累计约 12 秒，pip 累计约 37000 秒。服务 HTTP 仍可响应。

终止已核实的遗留 pip 后，服务立即输出
`pip list 2>&1 | findstr /I "request bs4 pandas lxml openpyxl"`
的 30 秒超时结果，随后因旧版 900 秒墙钟上限退出任务。
会话 `20260928-000750-ca6b` 此时落盘，最终记录 4 轮、6 次工具调用。
重启前页面保存在 `.diagnostics/agent-before-restart.html`。

问题在 Windows 的 `subprocess.run(shell=True, capture_output=True)` 超时路径：
杀掉 shell 后继续等待输出管道；后代仍持有管道时，超时收尾也会无限等待。
磁盘代码已经修改不代表运行中的 Python 服务已经加载修改。

修复使用临时文件收集输出、有界 wait，以及 shell 存活时清理进程树。
Windows 使用 taskkill /T /F，POSIX 使用独立进程组；清理失败明确报告，
不把未确认的后代清理说成成功。输出仅取有限首尾，避免读入全部输出。
这不是容器级进程隔离；主动脱离进程树的后台任务不在保证范围内。

另外补充模型等待/工具执行中的阶段信息，修正追问忽略轮数与成本参数，
删除过时墙钟常量，CLI 默认硬上限统一到 80，保留默认软上限 40。
单轮工具超限的标志也在正常轮次重置。

联网边界：没有专用搜索工具，但允许的 Python 可用 urllib 获取网页，
旧会话已有成功访问网页的记录。因此不能断言无法联网，也不能据此保证
可取得完整的福布斯榜单。系统提示要求实际核实来源、日期并披露数据缺口。
