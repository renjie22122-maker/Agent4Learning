## 解读边界

- 正确性检查独立于 Agent 自测；不能把离线机制测试通过混入真实模型成功率。
- 单 Agent 基线没有强制独立审查；review 组单独开启，均由相同外部裁判评分。
- 原生沙箱与 Windows 命令适配失败计入工具失败，不隐藏。
- 重复验证成本、长上下文等问题另见 tetris-run-audit.json；本轮小任务不代表大型项目性能。

## 本次实测结论与改进顺序

- 正式实测模型为 deepseek-flash，执行模式为 Windows native。4 类任务各 2 次，另有 1 次独立验收对照，共 9 次，外部验收 9/9、虚假完成 0。
- 9 次主 Agent 共 141 次模型请求、21 次工具失败。失败包括未安装 pytest/pip、Windows 下 tail/head 不可用、dir 的访问拒绝、错误工作目录及 Agent 自测发现的问题。最终通过不掩盖这些中间失败。
- 优先改进运行环境发现：先提供真实可用解释器、库、命令和目录能力，再生成测试方案；标准库足够时不要先尝试安装依赖。
- 多轮约束虽然通过，耗时 77–116 秒、20–34 次模型请求，说明简单任务也存在过多探索和测试扩张。应约束验收计划范围，而不是隐藏减少错误计数。
- 独立验收对照耗时 67 秒，其中实际等待约 36 秒，1 次验收、0 次 wait_agent 工具轮询；这是单例证据，不能据此断言多 Agent 更优。
- 对之前俄罗斯方块验收的只读审计：约 679 秒、20 次主模型请求、累计输入 9,648,935 tokens（含重复和缓存），2 次验收摘要不同，第二次之前记录的编辑仅 README；没有模型 wait_agent 空转。应研究按实际变更范围做增量验收，但不能直接跳过全部 Markdown。
- 三个新教学实验通过；37 项现有机制回归和 5 项评测器测试通过。它们不混入真实模型的 9 次能力统计。
- 初始调试批次 benchmark-20260928 因评测器误读等待状态而中止，已标记 INVALID，不纳入本报告。正式批次为 v2、followup 与 review 三组。

## 后续扩大评测

固定任务规格与环境，扩到至少 20–50 个不同任务、每任务 5 次；再加入跨文件修复、浏览器操作、RAG 证据引用、团队消息丢失/冲突以及执行中追加与取消。当前只覆盖小型样本，未运行官方 SWE-bench/AgentBench/τ-bench 数据集，也未做长期无人值守压力测试。
