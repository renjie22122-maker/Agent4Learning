# 如何开启子 Agent，如何调用工具，如何编写工具？

> 对应实验：`labs\lab_15_tools_subagents.py` · 运行：`python -m labs.lab_15_tools_subagents`
> 实测耗时 5.75s，13 条 `[VERIFY]`，6 条 `[BROKEN-REPRODUCED]`，全部数字来自真实运行。

## 一句话答案

**工具是"带契约的远程过程调用"，不是"给模型的一个函数"**——所以校验、超时、截断、幂等、权限
必须由**框架**强制，模型只负责产生"调用意图"。实测：v0 裸工具下 6 次非法调用有 4 次被静默接受、
写出 2 行脏数据；套上五件套后 6/6 被结构化拦回并自动修复，脏行 0。

**子 Agent 是"用钱和延迟买上下文隔离、并行度和权限收窄"**——只有这四个理由同时成立才值得开。
实测：3 个独立子任务并行把墙钟从 807ms 压到 266ms（代价 token 468 → 1397）；
而一个简单任务开子 agent 会 **贵 5.9 倍、慢 2.7 倍**（98 → 579 tokens，162 → 434 ms）。
**不要为了架构好看而拆。**

## 先复现：不做防护会发生什么

v0 是"裸工具"：注册表只做 `name -> fn` 映射，模型给的 dict 直接当 `kwargs` 用。
同一批脚本化输入打出六个故障：

```
[BROKEN-REPRODUCED] 参数幻觉：6 次非法调用 v0 只挡下 2 次（4 次静默通过、2 行脏数据入库）
[BROKEN-REPRODUCED] 无超时：工具对端挂死，没有工具级超时时整个 agent 实等 1644ms
[BROKEN-REPRODUCED] 返回值过大：单次工具返回 167.2KB = 42792 tokens，是上下文窗口 32768 的 1.3 倍
[BROKEN-REPRODUCED] 重复副作用：同一笔写被两个线程各执行一次 → orders 表 2 行重复
[BROKEN-REPRODUCED] 工具选择错误：含糊描述下 40 条意图只选对 26 条（准确率 0.650）
[BROKEN-REPRODUCED] 无限循环：脚本化模型反复调同一工具，跑到实验硬上限 20 次，白烧 1050 tokens
```

观测到的关键量：

| 观测量 | v0 实测 | 说明 |
| --- | --- | --- |
| `tool_calls_total` | 49 | 工具调用总次数 |
| `tool_arg_errors_total` | 6 | 参数非法次数 |
| 非法参数被静默接受 | 4 / 6 | 多余键被 `**kwargs` 吞掉，缺键等到下游才炸 |
| 脏行判定 | 2 行 | 缺 id / 金额为负 / 类型错 |
| `tool_latency_ms` | p50 4.2ms / p99 1072ms / **max 1642ms** | 尾部就是那个挂死的 `http_fetch` |
| 超大返回值 | 42,792 tokens | 是上下文窗口 32768 的 **1.3 倍**，直接塞爆 |
| 重复写 | 2 行 | `tool_idempotent_hits_total = 0` |
| 选错工具 | 14 / 40 条 | 例：`检索内部文档：多租户会话隔离` 应为 `search_kb`，实为 `calculator` |
| 含糊描述下 0 分意图 | 21 / 40 条 | 所有工具都匹配不上 → 只能按注册顺序兜底 |
| 工具描述 schema 文本 | 4,489 字符 | 每轮都进 prompt，是固定成本 |

**六类故障全都在框架层，不在 prompt 层。** 这是本 lab 最重要的归因结论。

## 根因分析

1. **参数幻觉不是模型的错，是"没有契约"的错。** v0 把模型给的 dict 直接展开成 `**kwargs`：
   多余的键被静默丢弃（所以 `topk=5` 被忽略、走了默认值），缺的键要等函数体里才 `TypeError`，
   类型错的会在**写入完成之后**才被发现。**没有 schema 就没有"参数非法"这个概念。**

2. **工具超时不能靠"调用方记得传 timeout"。** 挂死的 `http_fetch` 是"连上了但永不返回"。
   调用方 `join()` 不到就永远等。超时必须是 `Tool` 的**声明式属性**，由注册表统一执行。

3. **工具的返回值是"接口响应"，不是"给模型看的信息"。** 167.2KB 的响应体直接当字符串返回，
   等于把一份 HTML 塞进 prompt。**返回值必须有 token 上限，超了就截断 + 摘要 + 给 ref。**

4. **重试语义和幂等语义是两件事，但必须绑在一起。** 没绑的后果就是"重试一次 = 多写一行"。
   幂等键必须在**副作用之前**判定，而且同一个 key 要**串行化**（并发下也只写一次）。

5. **工具选择正确率是"描述质量"的函数，不是"模型能力"的函数。** 描述只写"做什么"
   （`search_kb: 搜索知识库`）时，40 条意图里 21 条**所有工具都得 0 分**，只能按注册顺序兜底。
   模型不是选错了，是**没有信息可选**。

6. **循环控制权不能交给模型。** 模型永远倾向"再做一步看看"，它没有"我已经绕了 3 圈"这个感知。
   终止条件必须是框架的三道硬闸门。

## 生产做法

### 一、工具框架：把契约写进 `Tool` 对象

一个生产级 `Tool` 至少要声明这些字段（本 lab 真实实现并有测试覆盖）：

| 字段 | 作用 | 不写会怎样 |
| --- | --- | --- |
| `name` / `description` | 给模型看的"什么时候用 / 什么时候**不要**用" | 选择正确率腰斩（见下） |
| `params`（JSON Schema） | 参数契约 | 参数幻觉直接进下游 |
| `timeout_s` | 工具级超时 | 挂死时整个 agent 卡住（实测 1642ms） |
| `retry`（max_retries / retry_on） | 重试策略 | 挂死的工具被无脑重试 → 停顿 × 重试次数 |
| `idempotent` | 是否可安全重试 | 重试 = 重复副作用 |
| `required_perms` | 权限要求 | 子 agent 继承父权限 → 越权 |
| `cost_usd` | 成本记账 | 无法做成本归因 |
| `max_result_tokens` | 返回值截断上限 | 42,792 tokens 塞爆窗口 |
| `needs_confirm` | human-in-the-loop | 危险操作静默执行 |

`ToolRegistry` 负责：注册、`describe()`（**真实生成并打印 JSON Schema 文本**交给模型）、
按名调用、**参数校验**。

**参数校验必须自己实现**（本 lab 手写了精简 JSON Schema 校验器，支持
`type` / `required` / `enum` / `minimum` / `maximum` / `pattern` / `maxLength` +
拒绝未知参数）。校验失败抛**结构化**错误 `ToolArgError{param, expected, got, message}`，
并把错误**渲染回 prompt 让模型重试**——这才是"修复"而不是"拒绝"：

```
tool_error(search_kb): param=$.topk expected=one of ['query','rerank','top_k'] got=5
  :: 不存在的参数 ['topk']；本工具只接受 ['query','rerank','top_k'] —— 请修正参数后重试
→ 第二次尝试带修正后的参数：6 次非法调用中 6 次修复成功；每条工具错误消息约 67 tokens
```

> 代价/边界：错误回灌会多花一次往返（约 67 tokens + 一次 LLM 调用）。
> 所以**只对"可修复"的参数错误回灌**；权限拒绝、需要人工确认这类不可修复的错误
> 直接返回终态，不要浪费一轮。

### 二、五个不同类型的工具，各自暴露一类工程问题

| 工具 | 类型 | 要处理的工程问题 |
| --- | --- | --- |
| `search_kb` | 只读、幂等、便宜 | 用 `agentlab.store` 真实检索；返回结果截断 + ref |
| `calculator` | 纯函数、幂等 | 除零 / 溢出 / 参数个数不对，全部要变成结构化错误 |
| `http_fetch` | 外部依赖、**非幂等**、会抖动 | 抖动 + 挂死 + 超长响应；`max_retries=0`（挂死时不重试） |
| `write_db` | **有副作用** | 幂等键 + 同 key 串行化 + `needs_confirm` |
| `dangerous_shell` | **危险** | `required_perms` + 人工确认票据 |

**为什么 `http_fetch` 要 `max_retries=0`**：挂死的对端不会因为你重试就活过来，
无脑重试只会把"停顿 1.6s"变成"停顿 1.6s × N"。重试必须挂在**同一个 deadline** 上，
且只对**幂等**工具开放。

### 三、工具描述质量 → 选择正确率（很实用的一节）

同一个工具集、同一批 40 条脚本化用户意图，只改描述文字：

| 描述版本 | 写法 | 选择正确率 | 0 分意图（所有工具都不匹配） |
| --- | --- | --- | --- |
| 差描述（v0） | `search_kb: 搜索知识库` | **26 / 40 = 0.650** | **21 / 40** |
| 好描述（v1） | 何时用 / 何时**不要**用 / 参数语义 / 与其他工具的区别 / 返回什么 | **39 / 40 = 0.975** | 0 |

好描述包含什么：
- **什么时候用**：`当用户问的是"文档/规范/历史记录里写了什么"时用我`
- **什么时候不要用**：`不要用我来做算术；不要用我来查实时状态`
- **参数语义**：`top_k 是返回条数上限，不是页码；query 应是自然语言问题而不是关键词堆`
- **边界**：`我只看得到当前租户的知识库；跨租户查询请用 admin_search（需要额外权限）`
- **返回什么**：`返回摘要 + ref；原文需要再调 fetch_by_ref`

> 代价/边界：描述变长 = 每轮 prompt 固定成本变高（v0 的 schema 文本已经 4,489 字符）。
> 所以描述要**精确而不啰嗦**：写清楚"边界与反例"，不要复述显而易见的废话。

### 四、工具调用的五道防线（顺序不能反）

1. **schema 校验**（含拒绝未知参数）→ 不通过就回灌错误让模型重试
2. **权限检查**（`required_perms ⊆ ctx.perms`）→ 不通过直接终态拒绝
3. **人工确认**（`needs_confirm`）→ 生成票据，例如 `CONFIRM-7f21`
4. **幂等判定**（副作用**之前**判，同 key 串行化）
5. **超时 + 截断**（`timeout_s` 用 worker join 实现；返回值超 `max_result_tokens`
   就摘要 + 给 ref）

实测修复效果：非法参数 6/6 拦回并修复；脏行 0；挂死工具实等 **1642ms → 403ms**；
工具进上下文的 token **42,792 → 324（-99.2%）**；重复写 2 → 0 行；
选对工具 26/40 → 39/40；循环从 20 次降到 3 次。

### 五、循环三闸门（工程硬编码，不能靠模型自觉）

1. **最大迭代次数** `max_iterations`（本 lab 实验硬上限 20）
2. **重复调用检测** `repeated_call`：相同 `(name, args)` 出现 3 次即停
3. **循环检测** `loop_detected`：检测到循环的名字序列即停，
   实测触发例：`search_kb -> calculator -> search_kb -> calculator`

实测：无限循环从 **20 次降到 3 次**，白烧的上下文 token 从 **1050 → 190**。

### 六、子 Agent：`SubAgentSpec` 的六个"独立"

| 维度 | 内容 | 为什么要独立 |
| --- | --- | --- |
| 独立 system prompt | 子 agent 只知道自己那件事 | 避免继承父级的无关指令 |
| 独立工具集 | **权限收窄**（子集，不是全集） | 实测 v0 继承父权限越权成功 3 次，v1 收窄后 0 次 |
| 独立上下文 | 不共享父级 messages | 避免污染 + 省 token |
| 独立 token 预算 | 例如 `token_budget=80` | 实测超预算 → `budget_exceeded`，父级不受影响 |
| 独立超时 | 例如 `timeout=600ms` | 与父级 deadline 取 min |
| 独立模型档位 | 小模型跑简单子任务 | 成本与质量的独立调节 |

`spawn_subagent(task, spec)` 用**线程 + `Deadline` 子预算**真实实现，并且必须做到：

- **失败不能拖垮父级**：子 agent 用不存在的模型 → `status=failed`，父级继续跑（实测通过）。
- **取消传播**：父 `deadline=300ms`、子 `timeout=600ms` 时，
  v0 实等 **619ms**；v1 **305ms**，`status=cancelled`。父超时必须能真的掐掉子。
- **结果回传协议**：只回传**结构化信封**（`status / summary / key_facts / tokens / usd /
  latency_ms / error`），**不回传完整轨迹**。实测：完整轨迹 251 tokens → 父级上下文只增 **82 tokens**。

### 七、什么时候该开子 Agent / 什么时候不该开

**该开（四个理由，缺一条就该重新评估）：**

| 理由 | 实测证据 |
| --- | --- |
| ① **上下文隔离** | 子 agent 的检索原文与试错轨迹留在子上下文，父级只收信封：轨迹 251 tokens → 父级只增 82 tokens |
| ② **并行探索** | 3 个独立子任务墙钟 **807ms → 266ms**（-67%），代价是 tokens 468 → 1397 |
| ③ **权限收窄** | 越权成功次数 3 → 0 |
| ④ **独立预算** | 子 agent 超预算只让自己 `budget_exceeded`，父级正常继续 |

**不该开（本 lab 的诚实数字）：**

| 场景 | 实测代价 |
| --- | --- |
| ① **简单任务** | 直接做 **98 tokens / 162ms / $0.000010**；开子 agent **579 tokens / 434ms / $0.000031** —— **贵 5.9 倍、慢 2.7 倍** |
| ② **强依赖父上下文** | 把父上下文塞给子 agent = 把隔离成本又付一遍，还丢了并行度 |
| ③ **需要多轮来回确认的任务** | 每次往返都要序列化/反序列化信封，延迟叠加 |
| ④ **只有 1 个子任务时** | 没有任何并行收益，纯粹多付一份 system prompt + 信封开销 |

> **判断口诀：子 Agent 买的是「隔离」和「并行」，不是「架构」。**
> 如果一个任务既不需要隔离上下文、也没有可并行的兄弟任务，开子 agent 就是纯亏损。

## 常见错误认知

1. **"工具就是给模型一个 Python 函数，它自己会传对参数。"**
   错。实测 6 次非法调用里 **4 次被静默接受**（多余键被 `**kwargs` 吞掉），
   写出 2 行脏数据。**没有 schema 校验，就没有"参数错误"这个概念**，只有"数据坏了"。

2. **"给工具加个 `try/except` 就够了。"**
   错。异常只能挡住"抛出来的错"，挡不住"多余参数被静默忽略""缺参数走了默认值"
   "类型错的金额写进了库"。必须**在调用前**用 schema 校验，并在失败时把结构化错误回灌给模型。

3. **"超时由调用方设置就行。"**
   错。挂死的工具是"连上了但永不返回"，调用方**没有机会**设置任何东西。
   超时必须是 `Tool` 的声明式属性，由注册表统一用 worker join 执行。
   实测不加超时实等 **1642ms**，加了之后 **403ms**。

4. **"工具返回什么就塞什么，反正是模型自己要看。"**
   错。实测一次返回 **167.2KB = 42,792 tokens**，是上下文窗口的 1.3 倍。
   正确做法是**截断 + 抽取式摘要 + 给 `ref` 按需回查**：42,792 → 324 tokens（-99.2%），
   而真正需要原文时一次 `fetch(ref)` 只花 151 tokens。

5. **"重试是好事，失败就多试几次。"**
   错。重试只对**幂等**工具安全。实测没绑幂等语义时重试直接造成 2 行重复订单。
   而且挂死的对端不会因为重试就复活 —— 重试必须挂在同一个 deadline 上。

6. **"模型选错工具是模型不够聪明，换个更大的模型。"**
   错。实测同样的模型，只把描述从"做什么"改成"何时用/何时不用/参数语义/边界"，
   正确率就从 **0.650 → 0.975**。**先修描述，再考虑换模型。**

7. **"多开子 Agent 就是更好的架构。"**
   错。实测简单任务开子 agent **贵 5.9 倍、慢 2.7 倍**（98 → 579 tokens，162 → 434 ms）。
   子 agent 只在"需要上下文隔离 / 有可并行子任务 / 需要权限收窄 / 需要独立预算"时才有价值。

8. **"子 agent 失败了父级就崩了，所以不要用。"**
   错。这是**实现问题**不是架构问题。正确实现下子 agent 用不存在的模型时返回
   `status=failed` 信封，父级继续跑；子 agent 超预算只让自己 `budget_exceeded`。
