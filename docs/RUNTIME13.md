# Runtime 13：团队通信与任务协作

子 Agent 可向 `root` 主 Agent 发送消息，主循环在步骤边界接收。普通成员结束后自动向父 Agent 发送完成或失败事件。主 Agent 尚有待送达消息时不能直接结束。

`send_agent_message` 返回消息 ID，支持 `reply_to` 和 `dedup_key`。同一去重键不能用于不同内容；无去重键但内容相同的待送达消息也会合并。每个成员最多积压 32 条普通消息，满时明确报错。系统事件单独保留。

`read_team_messages` 用 `after_seq` 增量读取自己收发的记录；`ack_team_message` 只能确认发给自己的消息。记录存于每个团队的 `coordination.sqlite3`。delivered 表示取出并交给步骤上下文的交付阶段，**不保证模型已处理**；进程可能在交付与写会话日志之间中断，应查询未确认记录。acknowledged 是接收方声明已处理，不是对结论真实性的验证。服务重启不自动重放子任务副作用。

`team_task` 支持创建、认领、阻塞、交接、释放和报告完成。认领与变更采用 SQLite 事务及版本检查，只有负责人或 root 能交接或释放；交接时通知接手成员。成员结束时仍在进行的认领工作自动标为 blocked，等待复核。done 不代表独立验收通过。

`followup_agent` 创建关联后续任务，记录 continued_from。使用当前工作区重新开始并携带前次结果作为参考，不恢复旧工具调用，不自动带回未合并隔离副本。嵌套任务的父任务必须仍存活。

子 Agent 开启上下文压缩，摘要通过同一计量客户端，使用团队模型并发与预算；只读权限和独立验收隔离仍保留。预算预估按 Unicode 消息、工具调用参数及工具说明计算；仍为预估，最终用量按 API usage 记录。

团队页增加任务板和最近 100 条通信记录。它不是跨机器团队系统，也尚无自动领导选举、自动故障转派或完整的对话循环检测。

教学实验：

- `python -m labs.lab_42_team_delivery`：内存队列丢消息，对比持久化、去重与确认。
- `python -m labs.lab_43_team_claims`：并发重复认领，对比事务版本检查与失败交接。

验证：离线测试覆盖持久化、确认权限、去重与积压、并发认领、任务交接、压缩预算、页面转义；真实 API 分别验证子 Agent 向主 Agent 汇报随机事实并确认，以及同伴之间传递随机事实。
