# runtime-17：交互、独立来源与本地向量检索

## 已实现的机制修复

- `request_user_input` 聊天卡片、持久化问题、宿主等待、答复后自动继续；等待不调用模型。普通答案与精确命令授权分离。拒绝、中止、过期、错误会话和重复提交均有测试。
- 根会话重启后可通过回答恢复上下文继续，界面重新连接 SSE。子任务重启仍标记 interrupted，答案保留并交由主会话协调，不自动重放未知操作。
- 验收子 Agent 获得宿主一致性知识库快照及只读检索工具，记录实际读取的原始分块与 SHA-256。仅有作者转录、缺少真实来源读取的通过声明会被拒绝。
- 独立验收通过后，宿主直接接受待决的完成声明；修复复验路径也可直接收尾，不再要求额外一次主模型声明。用户追加要求、文件变化和取消仍会阻止旧结论直接生效。
- 修复复验携带上次独立反例，要求优先验证反例与必要回归。调用方明确设置的步骤、时间额度会告诉模型，整项测试截止时间也传给子任务；不限额任务不新增限制。
- 新增本地 BGE embedding、SQLite 持久化向量与关键词融合检索，细节见 `RAG_HYBRID.md`。

真实浏览器验证卡片安全文本、草稿保留、没有默认提交、一次答复与流式恢复事件。新增教学实验 lab-50、lab-51，2/2 通过。

**后续外部补测揭示独立验收仍有漏检**：上述 CSV 在 30 位金额上抛 Decimal.InvalidOperation；多轮 v3 的第 0 个产物对 set 元素抛 TypeError，第 1 个通过混合类型补测。因此不能把基础评分通过解释为完整正确性通过。详细证据在相应目录的 `supplemental-decimal.json` 和 `supplemental-mixed-types.json`，没有覆盖原报告。

随后将跨类型相等、不可哈希输入、29/38/65 位金额及正负抵消纳入正式外部评分（suite v3），并加强独立验收的语义风险检查指导。外部评分新增正、负对照：正确实现通过，旧错误实现被拒绝。新增 6 项评分器测试全部通过。

加强评分的真实回归保存在 `.diagnostics/runtime17-strict-grading/report.json`：CSV 232.92 秒、多轮 254.09 秒，2/2 正常收尾且通过加强后的外部评分，保持 40 步 / 300 秒边界。这是开发期间的回归样本，不是独立未见题集成绩，也不能证明模型再无漏检。独立会话与知识库存储、无历史记忆召回的审计见同目录 `clean-summary.json`。

最终相关机制测试 44 项、评分器测试 6 项，合计 50 项；真实浏览器及两个教学实验另外通过。runtime-17 已在空闲状态重启加载，保留日志。

## 评测边界与剩余风险

40 次主模型调用是每个用户轮次的测试上限；300 秒是整个用例（含多轮和子验收）的外部时限。网页服务默认步骤上限为 0、总墙钟上限为 None，使用 unlimited 启动；不会默认在 40 步或 5 分钟中止俄罗斯方块等任务。单命令/API 超时和具体故障保护仍然存在。

这些是本项目定制回归，不是官方 SWE-bench 等榜单成绩。仍未证明各种任务都能及时收尾；模型可能过度设计、扩大测试范围或再次犯错。长任务还需要不同时间预算的完成率曲线、持续运行和中断恢复试验，不能只报正确产物数量。

向量检索实验的 12 个问题和 1000 条干扰资料上，Recall@5 从 0.667 到 0.833；真实大规模多领域语料、无答案拒答、ANN 索引和交叉编码器重排序尚未验证或实现。当前机制提高召回与来源可核对性，并不保证所有 RAG 答案正确。
