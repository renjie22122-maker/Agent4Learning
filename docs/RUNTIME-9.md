# Runtime 9：持续对话与多文件夹工作区

侧栏分为 Projects（项目）与 Chats（普通对话）：项目下排列其会话，即使没有会话也保留项目入口。
普通对话不归属项目，仍使用默认文件沙箱；旧默认目录会话归入普通对话，其他目录会话按原目录分组。
项目与普通对话分别提供新建入口，项目选择随提交表单传递，不会因为在另一标签页选择了项目而改变。

发送和追加提示使用 JSON POST，在原页面接收 SSE；输入失败保留草稿。
阅读旧消息时保持滚动位置，位于底部时跟随新输出。每次模型调用产生的文本
累计显示，完整保存在 `ui/turn.progress_messages`，完成后另列「本轮结论」。
旧版本未写入日志的流式片段无法补回。

在 `/workspaces` 创建命名工作区，每行 `别名=绝对目录`，第一行是主目录。
同一会话可以用 `@docs/readme.md` 等路径访问全部关联目录；
`run_shell(command="python check.py", cwd="@docs")` 在指定目录执行。
native/Docker 单条命令仅授权所选文件夹，未授权其共同父目录；
完全访问/本机模式沿用原有宿主权限。Git 辅助工具、后台进程和知识库默认仍以主目录为范围。

工作区文件夹不得重叠或重复，路径解析后验证边界，运行状态目录保持保护。
新会话保存文件夹快照；修改工作区配置只影响之后的新会话，恢复旧会话使用原范围。
会话侧栏按工作区分组。日志发现覆盖已登记工作区和最近目录。

完成证据摘要包含全部目录；任何目录的修改都会使旧证据失效。
子 Agent 及独立验收复制全部目录，合并前检查全部冲突，失败不部分覆盖。
与其他运行任务存在目录交叠时拒绝启动，避免多个主任务同时修改。

验证入口：

- `python -m unittest tools.test_multiworkspace tools.test_live_chat tools.test_live_features`
- `python tools/check_multiworkspace_live.py`：使用当前已配置 API，在临时目录读写和执行检查；该脚本显式选择可信本机执行。
- `node tools/test_chat_browser.cjs .diagnostics/chat-browser-fixture.json`：Playwright + Edge 浏览器回归。

教学实验建议：把已验证文件改在第二个目录，观察完成证据失效；
让父 Agent 与隔离子任务同时修改第二个目录，观察整批合并被拒绝；
任务运行中阅读旧消息并追加提示，观察滚动位置和文本累计。
