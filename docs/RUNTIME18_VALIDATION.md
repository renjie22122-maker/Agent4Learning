# runtime-18：验收等待与网络修复

针对 2026-09-29 的实际会话故障修复：

- 普通子任务完成闸门不再把宿主管理的独立验收当成作者待处理任务。`get_review_status` 返回验收 ID、状态、检查计划、耗时与结论；等待页每 10 秒更新一次宿主状态，不触发主模型轮询。
- `finish` 工具只显示“完成申请已提交”，不会在验收尚未开始时先宣称“任务结束”。
- 简单的明确进度询问由宿主回答，不追加验收要求；带其他要求的消息仍交给模型。需求变更会归档旧结论、请求取消旧验收，旧任务退出后才建立替代任务。验收只接收当前交付要求，不把整份历史对话当成新需求。
- 验收副本按本次变更文件引用复制 `.spill` / `.sources` 原始资料，记录 SHA256；不复制全部历史缓存。缺失来源报告受阻，副本或作者来源被修改均不能接受旧结论。引用扫描目前针对小于 2 MB 的常用文本文件中的字面路径；动态拼接路径仍需要显式落盘引用。
- 网络连接使用已校验地址对应的 socket family，正确处理 IPv6 四元组并回退到其他已校验地址。每次重定向仍检查权限与所有解析地址；私网地址仍拒绝，TLS 验证仍开启。
- DNS、连接、证书、HTTP、大小上限错误可区分。浏览器 broker 返回结构化错误，不向模型泄露宿主 traceback。可选 `allow_truncated=true` 返回明确 `complete=false` 的预览；预览不能通过完整来源验证。
- Windows 简单多行 `python -c` 会编码成单行载荷，保留完整 Python 语义及退出码。复杂的多行 shell 命令在执行前拒绝，提示先写脚本，避免 cmd.exe 只运行第一行却报告成功。
- 系统提示明确：PATH 中找不到工具不代表宿主没有硬件；搜索无结果不代表实体不存在；ERR_FAILED 不等于 404。

## 验证

回归入口：`python -m unittest tools.test_review_network_regressions`。
覆盖 IPv6、地址回退、私网拒绝、截断证据、状态询问、需求变更取消重验、隐藏验收闸门、来源缺失/篡改、无关历史引用、Windows 多行命令。

真实联网：example.com、docs.python.org/3/、httpbin.org/html 均成功返回完整内容。
真实 Edge 无头浏览器：Example Domain 正常；不存在路径明确返回 HTTP 404，不含宿主 traceback。
原生 AppContainer：多行打印 A/B 与退出码 7 实测通过。首次探针出现一次 15 秒无输出超时，随后单行、导入 base64、多行及非零退出码对照均正常；该首次超时原因尚未确定，不能据此宣称原生启动绝无偶发超时。
真实模型验收：`python tools/check_review_source_api.py --real 新目录`；测试作者使用固定脚本模型，验收者使用配置的真实 API。验收者读取来源快照、独立执行求和断言并通过，作者在最后允许步骤直接收尾。此测试不代表任意任务均可通过。

原始运行日志保留在本机 `.diagnostics/`，不纳入公开仓库。没有关闭 TLS 验证或放宽私网权限，也没有把历史失败改写为成功。
