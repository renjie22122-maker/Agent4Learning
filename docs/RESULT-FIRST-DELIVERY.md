# 通用成果交付修复

用户指出的问题是最终回复被验收与证据叙述占据，具体成果需要追问。修复不应演变成针对算法题禁止写文件或取消验收。

最终实现：

- 移除本轮曾尝试的算法题识别与专用完成分流；主循环完成逻辑保持原样。
- 每次主 Agent 模型请求注入通用交付规范：按任务需要正常执行工具和验收；最终回复先呈现可使用的成果，后给解释及简短验证情况。
- `finish.summary` 的工具说明从“做了什么、结果如何”改为“面向用户的实际交付”。代码、报告、计算与建议均适用；大型项目给准确位置和用法，不要求粘贴整个仓库。
- 主回复保留明确的宿主验收状态，去掉冗长的任务 ID 和作者历史总结说明。完整验收证据仍在日志和步骤中，不更改验收门槛。
- 列表解析要求 `-` 或 `*` 后有空白，负数不再被误当列表项；不是针对某个变量名或题目做排除。
- 代码复制脚本不再因缺少会话 ID 而退出；后续动态出现的代码块仍添加按钮。反馈操作使用当前会话 ID。

## 验证与限制

1. 通用最终实现的真实 API 项目测试：`.diagnostics/result-first-live-v1/report.json`。保存代码、执行检查、独立验收通过，最终回复有核心代码；主任务 4 次模型调用。没有禁用文件写入或验收。
2. 非代码真实 API 对照：`.diagnostics/result-first-noncode-live-v1/report.json` 返回订单数据表及分析。原测试因 `50.00%` 与 `50%` 的字面差异误报；`numeric-regrade.json` 对同一响应重新按数值核对，4 个占比及总数正确。未验证其业务建议的因果依据，不将数值通过称为整份分析正确。
3. earlier `same-tree-answer-live-v1/v2` 为已撤回的专用分流方案测试，不能代表最终代码。保留以说明过程，不能用其“零工具调用”作为现在的要求或承诺。
4. 原完整离线套件通过；最终调整后复测需求解析、运行契约、验收加固、普通对话和多轮上下文。环境缺失项仍为跳过。
5. 浏览器验证了空会话 ID 和动态新增代码块均有复制按钮。复制回调显示成功，但浏览器自动化虚拟剪贴板未读取到应用写入的系统剪贴板，未据此声称完成跨应用粘贴验证。

表达规范仍由模型遵循，单次实测不证明所有任务都稳定简洁。保留可检查的交付内容，比增加面向某道题的例外规则更重要。
