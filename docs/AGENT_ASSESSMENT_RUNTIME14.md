# Agent4Learning 运行时评估（runtime-14）

结论：当前适合作为个人开发助手和可观测的 Agent 教学平台，已有真实工具调用、递归子任务、隔离副本、审批、流式界面、知识库与可管理记忆。功能覆盖已经较广，但不能由“工具齐全”推导出“能可靠地长期无人值守”。主要短板是任务收敛、交付证据和跨层一致性。

本报告基于本机代码审查、俄罗斯方块会话日志、自动化回归和本轮真实 API 场景验证，不是与其他产品的统一基准排名。以下未完成项没有被本轮修复。

## 这次事故及修复

会话 `20260928-170042-30a3` 第一轮约 22 分钟、270 次模型调用；280 次工具调用中有 127 次 wait_agent。日志中的等待工具耗时合计约 1.89 秒，并非模型声称的几十分钟。两次被取消的验收分别约 3.7、6.6 分钟，累计约 399 万子任务 tokens。累计输入包含重复发送的历史，不能当作单次上下文长度。

本轮改动：

1. 模型使用的 wait_agent 等待完成、取消或团队消息，不因过期游标或计费版本更新立即返回；输出为简短状态、实际等待秒数和任务实际年龄。
2. 独立验收运行时由宿主等待，不重复调用主模型。用户插入消息、团队消息和取消仍可唤醒。
3. 验收结论增加 blocked/inconclusive，受阻能正常结束报告；主任务不会把它判为通过。
4. 验收子任务实际安装浏览器工具，增加可记录证据的 browser_check。默认精确文本匹配，失败会撤销旧成功证据。
5. 增加验收环境查询、有限计划及阶段进度记录。提示明确禁止为验收自制解释器或重写交付代码；这属于模型行为约束，并非所有偏离行为的静态证明。
6. pass 的 findings 必须为空且有当前工作区成功证据；正面观察写入 tests。fail 可以带具体反例结束，不要求先取得成功退出码。
7. 取消模型请求显示为“已中止”，不再作为模型调用异常。
8. 后续对话重置本轮修改范围，历史改动不再自动触发新的独立验收；历史记录及用户上下文保留。再次修改或主动重新验收仍可触发检查。
9. 明确 browser_preview 是后台测试浏览器，用户看不到其窗口；禁止把它描述为已经向用户展示网页。
10. 浏览器截图缓存排除出产物摘要和隔离变更比较，避免截图本身使验证失效。

## 剩余问题与优先级

| 优先级 | 领域 | 已有基础 | 当前缺口 | 建议 |
|---|---|---|---|---|
| P1 | 交付验收 | 独立上下文、隔离副本、浏览器/命令证据、受阻出口 | 退出码 0 和文本断言只证明某项操作成功；tests 仍是模型陈述，未结构化覆盖用户全部要求 | 为每条要求绑定检查 ID、执行记录和产物版本；用隐藏反例评测，区分“执行成功”和“要求满足” |
| P1 | 任务收敛 | 工具错误重复检测、可选预算、宿主验收等待 | 对“不断写新测试但不提高验收覆盖”的语义性空转检测不足 | 固定初始验收范围，比较新增证据、已验证要求和剩余阻塞；没有新增证据时请求决策，不简单按 token 数判死循环 |
| P1 | 验收快照 | 文件摘要与乐观冲突检查 | 复制整个工作区；无关项目、缓存与文件增多会增加复制、哈希及上下文成本；快照不是跨文件原子事务 | 优先支持 Git 提交/差异快照，或明确的变更文件与必要依赖清单；拷贝前后校验稳定性 |
| P1 | 用户可见交付 | 后台浏览器测试、文件与启动脚本 | 缺少统一的“打开成果”能力；模型容易把后台测试成功当作已向用户展示 | 独立预览入口与可点击产物卡片，显式区分后台测试、用户预览和正式发布；页面执行应与管理后台隔离 |
| P1 | 权限一致性 | AppContainer、本机/隔离模式、宿主审批、网页模式 | 网页工具策略和 shell 网络策略是不同层；本机模式具有宿主权限，原生文件隔离不等于离线 | 界面集中显示当前生效权限，记录授权来源；维护文件逃逸、子进程及网络绕过的负例矩阵，不只测试允许路径 |
| P1 | 多 Agent 恢复 | 递归、持久化通信、任务认领与交接 | 同一进程调度，重启后任务中断；嵌套副本不能直接恢复合并；后续任务不是原任务精确续跑 | 明确 continuation 与 resume；增加恢复向导、未确认消息处理和副本核验，不自动重放未知副作用 |
| P2 | 团队通信 | 消息 ID、去重、确认、共享状态版本检查 | delivered 不保证模型处理，确认也不证明理解；仍可能发生语义性来回讨论 | 加结构化问题/答复/阻塞事件、因果链和重复议题检测；避免简单确认引发双向循环 |
| P2 | 上下文 | 模型容量发现、spill、压缩、子任务摘要计量 | 容量阈值不是效率阈值；在 1M 窗口下可能长期重复发送大历史；token 预估是启发式 | 区分最大容量与目标工作集；将旧日志、重复状态转为按需检索；使用供应商 tokenizer 或校准估算 |
| P2 | RAG | 多格式导入、版本化分块、FTS5/BM25 | 主要是词法检索；跨措辞召回、长文结构和表格语义仍有限 | 先建立带正确答案与引用的评测集，再增加向量混合检索、重排和结构化分块；不要只以命中数量评价 |
| P2 | 长期记忆 | 用户选源、待确认、来源、范围、修改删除过期 | 候选提取与召回主要依赖规则/关键词；冲突、失效与经验适用条件仍需人工判断 | 明确条件、来源时间和替代关系；用户确认的决定优先，经验附适用版本与反例 |
| P2 | 计费 | API usage、缓存用量、估算标记、子任务费用 | 最后一次请求被中断时可能没有完整 usage；价格解析和供应商元数据存在差异 | 为每个请求展示实测/预留/未知状态，统一父子总账，保留价格快照和时间，不将估算称为最终账单 |
| P2 | MCP/插件 | 配置式 MCP HTTP JSON/SSE 子集、工具允许列表、技能导入 | 不覆盖完整协议生态；本地插件主要包装已有工具 | 对支持的协议版本、认证、取消、资源与错误恢复列出能力矩阵，逐项做互操作测试 |
| P2 | 多文件夹 | 文件路由、隔离副本、验收范围支持多个根 | 浏览器预览当前主要围绕主目录，工具之间多根体验尚不一致 | 统一文件引用、资源地址和目录选择，补每种工具的跨根及越界用例 |
| P2 | 工程测试 | 教学实验、离线回归、真实 API 正负例 | 仍混用独立脚本和 unittest；部分脚本导入时执行并退出，错误组合测试命令可能“退出成功但没跑全” | 统一测试入口和机器可读测试计数；每项报告耗时、样本数、失败产物；保留本次原始日志为回归用例 |

## 推荐顺序

先把稳定交付作为目标：每条需求都有对应证据、遇到环境受阻能结束、用户能打开成果、追问不重复开展无关验收。然后优化快照与上下文成本，再扩展 RAG、记忆和 MCP 生态。

不建议优先增加更多并行成员、更深递归或更大的默认预算。这些会放大现有证据、协调和收敛问题。预算继续可选；“不用固定上限”不等于“无需识别无效工作”。

## 本轮验证范围

包含离线回归、真实浏览器交互与断言，以及三类真实 API 验收：可运行网页通过、有缺陷函数被拒绝、没有命令执行权限时报告受阻。通过这些场景不等于所有复杂网页、依赖环境和长任务都已得到覆盖。Windows 权限边界仍需独立、受控的集成测试，不能由这些业务回归替代。
