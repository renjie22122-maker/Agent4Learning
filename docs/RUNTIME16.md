# Runtime 16：服务守护与保守恢复

桌面入口现在通过 `tools/service_supervisor.py` 启动服务。进程非零退出时按 2、5、15、30、60 秒退避重启；10 分钟内最多自动重启 5 次，之后保留现场并停止。正常退出不重启。守护进程使用操作系统文件锁避免重复启动，端口被占用时拒绝启动，不杀未知进程。每次启动日志保存在 `.agent-runtime/service-*.log`，状态记录在 `supervisor-status.json`。已有正常服务仍直接复用。

新增 `/recovery` 页面，可从工具与设置进入。会话增加持久化 `run/started`、`run/settled`、`run/cancel_requested`，不会把已完成或用户停止的运行重新启动。

自动续跑目前仅限本版本记录的只读任务：模型请求前已保存完整上下文和工作区摘要、日志无损坏、没有未知调用、没有权限升级或非只读工具、文件夹仍可用且内容不变、没有显式预算、会话未归档或删除。恢复保留只读权限，单条恢复链只尝试一次。模型请求可能重新计费，不能保证提供方侧恰好执行一次。恢复沿用会话上下文继续当前请求，不宣称恢复模型内部推理状态。

允许写入、运行命令、子任务等情况一律进入需要核对列表，用户进入原会话检查现场后继续。不会自动调用日志中的工具。旧版本没有运行记录的会话不会被批量唤醒。日志落盘失败时，不再向内存发布该事件；恢复打开已有日志会继承序号，避免初始化权限事件造成序号重置。

测试包括真实子进程首次崩溃后重启、正常退出不重启、连续崩溃退避、未知操作不重放、取消不恢复、文件变化拒绝、只读上下文恢复及日志单调性。

边界：这不是 Windows 系统服务，不包含电脑重启自动登录启动；守护进程本身被杀后不会自行复活。仅监督进程退出，不因模型慢或 HTTP 暂不可达而杀任务。写任务、子 Agent 编排、审批状态尚不能自动精确恢复；不存在通用的外部副作用恰好一次保证。
