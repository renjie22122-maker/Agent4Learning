# 源码评价修复记录（runtime-19）

后续四项升级已经实现，见 [runtime-20 升级记录](RUNTIME20_UPGRADE.md)。下文保留 runtime-19 时点的修复与边界。

本轮按四份外部源码评价核对实现。评价分数不作为能力基准；以下区分已经修复的缺陷、现有能力和仍未实现的架构建议。

## 已修复

| 问题 | 修改与验证边界 |
|---|---|
| 长历史只取每条前 1500 字符、总共前 24000 字符，却删除整段历史 | `compaction.py` 将待摘要记录完整序列化后分段处理；所有分段成功且摘要确实缩短才替换。用户原始任务、补充约束和近期工具协议边界保持原文。失败保留摘要阶段输入；此前独立执行的工具剪枝仍生效。累计所有摘要调用用量。并不保证模型摘要在语义上无损。 |
| 子任务权限只在创建时配置 | 每次工具执行重新计算自身与祖先的权限交集，父级撤回写入、shell 或工具许可会向后代传播。网页请求仍由独立网络 broker 逐次检查授权；不把网页 broker 等同于允许任意 shell 联网。已开始的外部操作无法靠权限撤回追溯撤销。 |
| 本机命令可能继承服务环境中的凭据 | `Workspace.run`、后台命令、批准的宿主命令使用最小环境白名单，排除 API 密钥、云凭据和 Python 注入环境变量。不是文件系统隔离的替代品：完全本机执行仍按宿主账户可读范围访问文件。 |
| 教学网关只有内存幂等，重启或换 trace 后重复操作 | 新增 SQLite 逻辑操作账本。宿主传入稳定 `logical_operation_id`，绑定租户、用户、工具及参数；已完成返回持久化结果，截断结果原文可跨重启回取；未知结果禁止自动重放，参数变化拒绝。缓存命中前重新校验权限。副作用工具不做自动重试。此能力是 Capstone `ToolRegistry` 的显式接口，不宣称任意 shell 已获得 exactly-once；真实 CodingAgent 仍沿用未知副作用暂停恢复策略。 |
| 教学网关总次数写死为 12 | `ToolRegistry(max_calls_per_request=...)` 可配置，0 表示不设总次数限制；每工具上限仍独立。计数按租户、用户和请求隔离，重置需身份上下文。这与真实 CodingAgent 的每步工具批量上限不是同一概念。 |
| 编排与供应商细节耦合 | 增加 `ModelClient` 协议、客户端工厂、验收模型配置和摘要客户端适配边界。子任务调度不再直接判断 DeepSeek 配置。当前仍是 OpenAI 兼容传输，没有假装实现原生 Anthropic/Gemini API。 |
| 主循环承担验收策略 | 抽出 `ReviewLifecycle`，保留既有完成、等待、失败处理语义。是逐步拆分，不是已完成整个主循环重构。 |
| 记忆重复、注入半截 JSON | 按相关性加轻量时效排序，完全相同内容合并召回但保留所有来源。按完整条目控制注入长度，只记录实际召回 ID；不同内容不会自动合并，矛盾需核实。 |

## 已有能力与评价中的误读

- 项目已有 Windows AppContainer 和 Docker 后端；隔离副本本身确实不构成操作系统沙箱。
- 严格离线预检失败时拒绝执行；用户已选择的“原生文件隔离＋宿主网络”仍保持原设置，不能宣传为严格网络隔离。
- 评价时默认实验实际为 47 个，另有 3 个 Windows 实验，编号存在空档。新增 lab-52 后为 **48 个默认＋3 个原生实验**。
- 用户补充约束此前已逐字保留；本次重点修复的是其他历史在摘要输入端被静默截断。
- 团队任务 `done` 已明确是工作者报告，不等于验收或合并成功；保留这个区别，不添加允许模型自行宣称“验证完成”的状态捷径。
- RAG 已有本地 BGE、关键词与向量融合、查询扩展和来源快照；不能把“没有 ANN”说成“没有向量检索”。

## 验证

- `tools/test_review_hardening.py`：13 项故障导向回归，包括分段尾部、第二段失败、祖孙权限撤回、真实子进程环境、跨重启去重、未知结果、截断原文持久化、权限重新检查、记忆去重与 JSON 完整性。
- 其余相关测试：77 项通过；合计 90 项（89 项联合运行＋新增的持久化长结果测试单独通过，完整新增套件 13/13）。
- `tools/test_compaction.py`：六组检查通过；合成历史峰值输入从 133726 降到 33730 tokens。这是合成场景，不是模型能力基准。
- `verify.py --jobs 4`：48/48，155 条 VERIFY 指标。
- 新实验 `lab-52-durable-operations`：对比跨进程内存去重失效与持久化逻辑 ID，重复副作用 1→0，并验证未知操作拒绝重放。
- 真实 API 来源快照验收通过：脚本父任务四步，模型验收子任务消耗 31287 tokens，读取来源、核验摘要、计算总和并正常收尾。报告位于本机 `.diagnostics/runtime19-source-api/report.json`（不公开提交）。

- 真实 API 分段压缩通过：2 次调用，共 23004 tokens，历史尾部文件名与用户约束均保留；按当前价格快照估算 $0.0046926。报告 `.diagnostics/runtime19-compaction/report.json`。单次用例不证明语义无损。

## 尚未实现或尚无证据支持

1. **大知识库**：仍是分批扫描的精确向量索引，没有 ANN/分布式索引、独立 cross-encoder reranker 或百万分块性能证明。下一步应先测 recall@k、MRR、p95、增量更新一致性，再选择索引后端。
2. **语义长期记忆**：本轮只改关键词排序、去重与安全注入；尚未建设记忆向量索引、自动冲突消解或遗忘策略。知识库向量能力不等于记忆已有向量能力。
3. **自治团队**：有递归委派、消息和任务认领，但没有经过基准验证的自动组队与动态规划策略；不以“多开几个 Agent”代替任务完成率证明。
4. **架构**：主循环仍较大。后续可继续拆出回合执行、上下文维护和恢复服务，需逐步守住现有协议和崩溃恢复行为。
5. **跨模型评测**：本次是真实配置模型的定向集成测试，不是 SWE-bench/GAIA 官方分数，也不是跨供应商回归矩阵。
6. **安全**：最小环境、能力检查和来源隔离不代表完全抗提示注入，更不代表任意主机、依赖和本机执行模式下都安全。

这些项目保留为明确的后续建设项，不标记成已修复。
