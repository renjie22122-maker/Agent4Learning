# 运行契约改进

本轮落实工具守卫、验收事实和评测可审计性。参考用户提供的 Harness 架构对比思想，不采纳未经共同基准验证的产品评分。

## 执行边界

`CodingAgent.tool_guards.register(name, callback)` 注册受信宿主回调。回调接收不可变 ToolRequest 和参数深拷贝；返回 None 表示不反对，非空字符串表示拒绝。拒绝、异常或非法决定均中止执行，后续回调不能放宽。通过回调后仍在调用处计算实时权限交集并检查参数。插件回调不是 OS 沙箱，也不能授予新权限。

这是真正接入工具执行入口的扩展点，但不是整个内核的依赖倒置；目前不允许模型安装、替换这些守卫。

## 完成事实

独立验收通过后保存 `delivery/finalized` 事件，包含验收 ID、工作区 digest、测试和 passed 状态。发布前再次比对任务和工作区版本。LoopResult 分别保存 author_summary、acceptance 和展示用 summary。页面已有 summary 渲染入口会优先显示宿主最终结论，并明确作者文字写于提交验收前。

验收 Agent 的 JSON 输出保持原样，避免破坏上层解析。未经独立验收的结果不会凭空生成 passed 状态。新增事件尚不是所有运行状态的唯一来源，完整事件投影重构仍未完成。

## 评测格式

五个报告生产入口新增 `evaluation`，保留旧字段供现有工具兼容。schema_version=1，kind 区分 task_benchmark、integration、retrieval 和 runtime_contract。记录 Git commit/dirty、Python/OS、配置、计划与实际 case 数、完成状态、各类结果和明确分母。

passed/failed 是已评分结果；error/skipped/unknown/measured 单列，不能伪装成评分通过。pass_rate 仅针对已评分样本，应连同错误和覆盖率读取，不能单看百分比。检索性能测量没有预设通过阈值时标为 measured。case 不等同于任务数或重复次数。

`python tools/inspect_evaluations.py PATH` 只读识别旧报告；未知格式显示 null，不生成虚假的 0/0，也不改写历史证据。

历史自评报告按 964eb3e 的源码引用复核；缺失私有历史证据标为未复核。该检查不是当前能力评分。

## 验证范围

- 新增 lab-56，含工具权限负对照、参数不可被守卫改写、异常拒绝、过期验收拒绝、机器输出兼容和报告缺失值实验。
- Windows 超时实验打开本次创建的子进程句柄，验证超时后该进程确实退出，不以 CPU 为零代替退出。
- 离线套件和 lab 执行器使用 ProcessSupervisor，超时、正常退出和异常均清理本次进程树；不终止不属于本次执行的浏览器。
- 浏览器预检只跳过明确的启动环境限制；未知启动错误和实际页面断言失败仍报错。
- 真实 API 来源快照验收通过：37,088 reviewer tokens；对应私有报告 `.diagnostics/runtime21-source-review/report.json`。这是单次集成验证，不能证明整体成功率提高。
- 本轮离线入口执行 45 个测试脚本，无失败；缺失历史证据和受限浏览器明确跳过。另在宿主单独执行浏览器正负对照，3 项通过。默认教学实验 51/51 通过；11 项运行契约回归通过。不包含完整 Windows 原生隔离套件和可选 ANN 大规模测试。

## 尚未完成的结构性工作

15+ 任务 × 3 次的分层真实基准、完整运行状态投影、可替换 Sub-Agent provider、基于实测收益的自动委派策略、按任务风险配置验收强度，仍需独立设计和验证。本轮对委派范围的改进主要是提示规范，不能声称模型已稳定做出最优委派。

本轮不改用户配置的任务预算和权限，不重放旧任务，不清空历史数据。
